# Configuration

The installer creates `/etc/ultimate-updater-notify/config` from `config.example` only when the file does not already exist. Reinstalling preserves the operator-owned configuration.

## ntfy

Required configuration:

```bash
NTFY_URL="https://ntfy.example.com/ultimate-updater"
NTFY_TOKEN_FILE="/etc/ultimate-updater-notify/ntfy-token"
NTFY_TITLE_PREFIX="Ultimate Updater"
```

`NTFY_URL` is the complete topic URL. Prefer HTTPS whenever the publisher crosses an untrusted network boundary.

The token file must contain only the ntfy access token and should remain readable only by root:

```bash
sudo install -d -m 0750 /etc/ultimate-updater-notify
sudo install -m 0600 /dev/null /etc/ultimate-updater-notify/ntfy-token
sudoedit /etc/ultimate-updater-notify/ntfy-token
```

The notifier uses native ntfy Bearer authentication. The token is piped to curl as a header file through standard input, so it is not placed in curl's process arguments. Apprise is not required at runtime.

## Guest access

Guest access is owned by Ultimate Updater. If Ultimate Updater defines a VM under `/etc/ultimate-updater/VMs/<vmid>` and checks it over SSH, its normal key-based/non-interactive prerequisites must already work. The companion no longer opens its own SSH session or maintains a separate sudo/package-manager contract; it delegates the read-only inventory check to the accepted Ultimate Updater 5.1 interface.

## Optional Gatus dead-man heartbeat

Successful **systemd-scheduled** checks can publish to a Gatus external endpoint:

```bash
GATUS_HEARTBEAT_URL="https://gatus.example.com/api/v1/endpoints/<endpoint-key>/external"
GATUS_HEARTBEAT_TOKEN_FILE="/etc/ultimate-updater-notify/gatus-heartbeat-token"
```

Leave both values empty to disable heartbeat delivery. Use the external endpoint key generated by Gatus for `<endpoint-key>`; Gatus accepts results at `POST /api/v1/endpoints/{key}/external?success=...`.

Create the Gatus token file with the same root-only model as the ntfy token:

```bash
sudo install -m 0600 /dev/null /etc/ultimate-updater-notify/gatus-heartbeat-token
sudoedit /etc/ultimate-updater-notify/gatus-heartbeat-token
```

Only the packaged systemd check service sets `UUN_SCHEDULED_RUN=true`. A direct operator invocation of:

```bash
sudo /usr/local/libexec/ultimate-updater-notify check
```

does **not** advance the heartbeat.

The Gatus Bearer token uses the same header-through-stdin pattern as the ntfy token. If Gatus does not acknowledge a scheduled heartbeat, the scheduled check fails and the normal ntfy failure path reports the heartbeat-delivery problem.

## Secret handling

- Do not commit ntfy or Gatus tokens.
- Keep token files root-readable and separate from the public repository.
- Do not place Bearer tokens in URLs, command-line arguments, or example configuration.
- Keep deployment-specific hostnames and credentials outside the reusable public product source.
